# Scientific Data — Submission Guidelines

How to prepare and submit a manuscript to *Scientific Data*. Please see the journal’s Aims and Scope for advice on what to consider before doing this.

|  | Data Descriptor | Article |
|---|---|---|

| Peer-reviewed? | Yes | Yes |

## 2. Deposit the dataset

Data Descriptors are associated with datasets reviewed alongside the paper.

For first-round review, data must be available for anonymous download through any URL. This may be the final repository link or a temporary location such as cloud storage.

From the second review round onward, data must be public and available in a formal data repository that meets journal policy.

In most cases, the journal recommends depositing the data in the repository from the start.

Sharing is also required for Articles where relevant to the results.

## 3. Prepare the manuscript

### General

Submissions should be clear and understandable to scientists from diverse backgrounds. Avoid technical jargon where possible and define necessary terms on first use.

There are no strict rules for format, font size, or style, provided the mandated headings are included. The journal does not require article templates.

Authors are responsible for copy editing or language editing if needed.

### Title and Abstract

Titles must not exceed 110 characters including spaces. Avoid acronyms, abbreviations, unnecessary punctuation, colons, and parentheses.

Use objective, technically descriptive titles. Do not include dataset brand names, self-constructed acronyms, or advertising claims such as “novel,” “first,” “AI-ready,” or “open.”

The abstract should not exceed 170 words. It should describe the data and possible uses, but should not claim new scientific findings. Do not include URLs or use subheadings.

### Authors and Affiliations

Affiliations should include enough detail to reach the author, including department, institution, and country where relevant. Full postal addresses are not required.

Corresponding author email addresses should be provided.

Equal contribution footnotes may be used. Other status labels such as “Senior Author” are not used.

### Background and Summary / Introduction

For Data Descriptors, this section should explain the dataset, motivation, and potential reuse value. Prior publications using the data should be cited and briefly summarized.

For Articles, the Introduction should explain why the work was performed and what value it adds.

Avoid subjective claims about novelty, impact, or utility.

### Methods

For Data Descriptors, Methods should describe how the data were created, including experimental design, acquisition, and computational processing.

For secondary datasets, describe input data in enough detail for readers to source the exact data used. Use data citations for datasets with DOIs or formal metadata.

Do not include general results or analyses.

For Articles, describe the scientific process used to generate the output or study. Avoid advertising-style descriptions.

### Data Record

This section applies to Data Descriptors only.

It should explain what the dataset contains, where it is hosted, the data files and formats, folder structure, and definitions for unclear fields or metadata.

External datasets should be cited using the journal’s data citation format.

Do not include summary statistics here.

### Data Overview

This optional section applies to Data Descriptors only.

Data Descriptors should not contain results, discussion, or analyses. However, authors may include a short Data Overview section with 1–2 figures or tables and one paragraph of text.

Large analytical sections will be removed or reduced.

### Technical Validation

This section applies to Data Descriptors only.

It should describe experiments, analyses, or checks supporting the technical quality of the dataset.

### Usage Notes

This optional section applies to Data Descriptors only.

It may include technical notes to help researchers reuse the data. It should not be used as a conclusion, sales pitch, or worked case study.

### Data Availability

For Articles, a Data Availability statement is required. It should describe any shared non-code output, such as datasets, ontologies, schemas, policies, platforms, or other hosted materials.

If no data are shared, state that no data are shared as part of the article.

For Data Descriptors, the Data Record is the main section describing the data, but a short Data Availability statement is also required. This should repeat key accession numbers, URLs, and dataset reference numbers.

### Code Availability

All publications require a Code Availability statement.

The statement should say whether custom code was used and how it can be accessed, including restrictions. If no custom code was used, state this.

This section should appear immediately before the references.

### Acknowledgements, Author Contributions, Funding and Competing Interests

Acknowledgements are optional and should briefly acknowledge non-author contributors. Do not use this section for funding.

Author Contributions are required for all articles.

Competing Interests statements are required for all articles.

Funding statements are required for all articles, even if there was no external funding.

### References

References should be numbered sequentially. Only published, accepted, or recognized preprint-server works should appear in the numbered list.

For LaTeX submissions, references must be embedded directly in the `.tex` file. Do not use separate `.bib` or `.bbl` files.

The correct abbreviation for *Scientific Data* is **Sci. Data**.

### Citing Data

Datasets described or used in the manuscript should be cited in the text with superscript numbers and listed in References like literature citations.

Data citations should include author list, title, repository name, URL, and year where available.

Stable persistent identifiers such as DOIs are strongly encouraged.

### Figures and Tables

Manuscripts may reference figures, tables, and supplementary information.

Do not include internal hyperlinks to manuscript elements, as these are removed during typesetting.

### File Requirements for First-Round Review

For first-round peer review, the minimum requirement is a single PDF for the main article and, where relevant, a PDF for Supplementary Information.

The article file should include all figures and tables with captions.

### Covering Letters

A covering letter file is technically required by the submission system, but specific content is not required. Covering letters are not used for editorial suitability decisions.

Useful information may include suggested reviewers, non-preferred reviewers, technical conflicts, or collection submissions.

Do not include APC waiver or discount requests in covering letters.

For revised manuscripts, submit a separate Response to Reviewers file rather than a covering letter.

## 5. First Round Peer Review

The journal first performs a quality check for basic peer-review requirements, including file availability, data availability, code availability, and journal scope.

In-scope manuscripts that meet technical requirements are sent for peer review. The journal states that it does not assess perceived impact at this stage.

The paper is then assigned to an Editorial Board Member or, if unavailable, an in-house editor.

Reviewer sourcing is usually the longest part of peer review. At least two reviewers are required.

Reviewers are typically given 10 days, with extensions possible.

After reviews are received, the editor recommends Accept, Revise, or Reject.

## 6. Revised Manuscripts

### What to Expect

If revisions are requested, authors are invited to revise and resubmit. One month is provided, with flexibility if needed.

The journal aims for a two-round review process.

Second-round review begins with a more detailed quality check to ensure the paper is ready for possible publication.

### General Requirements

Revised submissions require:

- Main article file in `.docx` or `.tex`
- One separate file per figure
- Supplementary information document, if relevant, as PDF
- Oversized tables as `.xlsx` or `.csv`
- Response file addressing all reviewer and editor comments as PDF
- Optional PDF with highlighted changes

### Figures

Data Descriptors and Articles should generally not have more than eight figures.

Figures should follow Nature image policies.

Authors must obtain permission for copyrighted figures or illustrations.

Figures should be numbered with Arabic numerals in order of appearance.

Figure lettering should use a clear sans-serif typeface. Use Symbol font for Greek letters.

Figures should have white backgrounds and be readable after reduction.

Multipart figures should be combined into one file and labeled with lowercase bold letters.

Figure legends must be no more than 350 words.

### Figures for Peer Review

At initial submission, figures may be embedded in the article file or uploaded separately.

At revision, all figures must be uploaded separately.

### Figures for Publication

Each complete figure must be supplied as a separate file.

Multipart figures must be arranged as a single image file.

Avoid excessively large files.

### Tables

Tables may be embedded in the Word document or supplied separately.

Data Descriptors and Articles should generally have no more than ten tables.

Avoid complex nested or merged-cell structures.

### Oversize Tables

Tables that cannot fit on one A4 page are hosted as Supplementary Tables.

Very large tables should be deposited as part of the repository dataset rather than submitted as supplementary material.

### Equations

Equations should appear in the main text.

Referenced equations should be numbered, for example `(1)`.

### Supplementary Information

Scientific Data discourages supplementary text, figures, or tables where the material can be included in the main manuscript.

Supplementary Information should not be used to add results, discussion, or analyses to a Data Descriptor.

Supplementary documents must be PDF files and should be self-contained.

Supplementary figures and tables should be numbered separately, for example `Figure S1` and `Table S1`.

Supplementary files should be as small as possible, with a maximum size of 10 MB.

### Instructions for LaTeX Users

For revised manuscripts, submit a single standalone `.tex` file as the Article file.

The `.tex` file must compile without separate `.bib`, `.bbl`, style, or dependency files.

Do not upload a compiled PDF or `.zip` archive.

The journal does not recommend LaTeX templates.

Use numerical citations and include the reference list directly in the manuscript file.

Do not include internal hyperlinks through commands such as `\cref`.

### Consortia Authorships

A consortium author is a group name in the author list.

Consortium authorships should only be used where the full author list would be excessively long, such as 100 or more people.

All consortium members are considered bona fide authors and must be listed with affiliations at the end of the Author Contributions statement.

Do not use consortium authorship to credit people who did not actively participate in creating the paper or dataset.

## Articles in Press

Once accepted, the article is published immediately as an Article in Press.

An Article in Press is an early access version of the accepted manuscript. It may undergo further editing before becoming the Version of Record.

Corrections are not made to the Article in Press; they are handled during proofing.
